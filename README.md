# perepost

**English:** a self-hosted bot that mirrors channel posts between Telegram and [MAX](https://max.ru),
including formatting, photos, videos, albums and files. It supports many-to-many routes,
a persistent SQLite queue and loop protection. One Go binary or Docker image.
The documentation below is in Russian, since MAX is a Russian messenger.

---

Бот переносит новые посты между каналами Telegram и MAX. Для каждого направления задаются свои
маршруты. Можно связать один канал с несколькими или свести несколько каналов в один.

## Что переносится из Telegram в MAX

| В Telegram | В MAX |
| --- | --- |
| Текст и подпись | С разметкой: жирный, курсив, подчёркнутый, зачёркнутый, моноширинный, цитата, ссылки |
| Спойлер | Обычный текст |
| Репост | Тот же пост со строкой «Переслано из …» и ссылкой на оригинал |
| Фото, живое фото | Фото (живое — кадром) |
| Видео, GIF, видеокружок | Видео |
| Альбом | Одно сообщение со всеми фото и видео |
| Файл, музыка | Файл — отдельным сообщением (в MAX файл не может соседствовать с другими вложениями) |
| Голосовое | Аудио |
| Опрос, геоточка, контакт, платный пост, длинный rich-пост | Ссылка «Открыть пост в Telegram» |
| Стикеры, служебные сообщения (закреп, смена названия) | Пропускаются |

Длинный пост, который не влезает в лимит MAX (4000 символов вместе с разметкой), уходит
несколькими сообщениями подряд. Режется по абзацам, разметка в каждой части закрыта.
Уведомление подписчики MAX получают только по первому сообщению.

## Что переносится из MAX в Telegram

Текст и подписи сохраняют жирный, курсив, подчёркивание, зачёркивание, моноширинный текст, цитаты
и ссылки. Фото и видео отправляются альбомами до 10 вложений, аудио и файлы — документами.
Длинный текст после альбома и дополнительные вложения публикуются тихо. Если часть поста
перенести не удалось, бот добавляет ссылку на публичный оригинал, если MAX её прислал.
Облачный Bot API принимает документы и видео до 50 МБ. У локального Bot API лимит в perepost
составляет 2 ГБ суммарно на пост. Лимит фотографии — 10 МБ.

## Ограничения

- **Файлы больше 20 МБ** облачный Bot API Telegram не отдаёт. Вместо такого видео в пост
  добавляется ссылка на оригинал — или включите свой сервер Bot API, и лимит станет 2 ГБ
  (см. [«Видео больше 20 МБ»](#видео-больше-20-мб)).
- **Правки и удаления** включаются для каждого маршрута отдельно. См.
  [«Синхронизация правок и удалений»](#синхронизация-правок-и-удалений).
- **Сторис** не переносятся: боты Telegram их не получают, а у ботов MAX нет сторис.
- Ссылка на оригинал работает только у публичного канала.
- Очередь и идентификаторы публикаций хранятся в SQLite. Для каждого набора маршрутов запускайте
  один экземпляр perepost с постоянным `STATE_FILE`.
- Если платформа могла принять публикацию, а ответ потерялся, запись получает статус
  `uncertain`. Пересылка **из** канала, в который бот пытался опубликовать пост, ждёт проверки
  результата. Входящие посты этого канала продолжают записываться в очередь. См.
  [«Неизвестный результат публикации»](#неизвестный-результат-публикации).

## Подготовка

1. **Бот Telegram.** Создайте нового бота у [@BotFather](https://t.me/BotFather) и добавьте его
   администратором каждого канала-источника. Права ему не нужны: Telegram присылает посты канала
   только администраторам. Для канала-получателя включите право публикации. Для получения постов
   нужен отдельный бот — если у бота уже настроен вебхук другого сервиса, perepost
   откажется запускаться, чтобы не сломать чужую интеграцию.
2. **Бот MAX.** Создайте бота по [документации MAX](https://dev.max.ru/) и добавьте его
   администратором каждого канала-получателя с правом публикации. Подойдёт и существующий бот:
   для Telegram → MAX достаточно права публикации. Для MAX → Telegram боту нужно право чтения
   сообщений в каналах-источниках и своя подписка на вебхук.
3. **Доступ к MAX.** Сервер должен достукиваться и до `api.telegram.org`, и до API MAX. API MAX
   подписан сертификатом Минцифры, которого нет в стандартных наборах, поэтому `curl` нужен
   корневой сертификат из репозитория (бот носит его с собой, ставить в систему ничего не нужно):

   ```bash
   curl --cacert <(curl -fsSL https://raw.githubusercontent.com/smotim/perepost/main/certs/russian_trusted_root_ca.pem) \
     -H "Authorization: <токен MAX>" https://platform-api2.max.ru/me
   ```

   В ответ должен прийти JSON с данными бота.

## Запуск в Docker

Нужны два файла: [`docker-compose.yml`](docker-compose.yml) и `.env` по образцу
[`.env.example`](.env.example). Клонировать репозиторий не обязательно.

Для одной пары каналов всё задаётся в `.env`:

```env
TELEGRAM_BOT_TOKEN=123456:ABC...
MAX_BOT_TOKEN=...
TELEGRAM_CHANNEL=https://t.me/my_channel
MAX_CHANNEL=https://max.ru/my_channel
```

```bash
docker compose up -d
docker compose logs -f
```

В журнале должно появиться `пересылаю посты routes="«…» → «…»"`. Для закрытого канала вместо
ссылки укажите числовой id. Если канал MAX не найдётся, бот выведет список каналов, где он
состоит, с их id.

Образ собран для amd64 и arm64 (подходит, например, для бесплатных ARM-машин Oracle Cloud). Тег
`latest` — последний релиз; чтобы обновления не приезжали сами, укажите версию:
`ghcr.io/smotim/perepost:0.1.0`.

## Несколько каналов

Оставьте `TELEGRAM_CHANNEL` и `MAX_CHANNEL` пустыми и опишите маршруты в `config/config.yaml`
рядом с `docker-compose.yml` (пример — [`config.example.yaml`](config.example.yaml)):

```yaml
routes:
  - from: https://t.me/my_channel
    to: https://max.ru/my_channel

  - from:
      - https://t.me/my_news
      - "-1001234567890"
    to:
      - https://max.ru/my_news
      - https://max.ru/my_digest
```

Каждый пост любого канала из `from` уходит во все каналы из `to`. Канал может встречаться в
нескольких маршрутах. Токены в файл не пишутся — они остаются в `.env`, чтобы файл маршрутов
можно было спокойно показывать и копировать.

Порядок обработки соответствует порядку приёма внутри каждого канала. Каналы обрабатываются
параллельно.

## Из MAX в Telegram

Добавьте отдельный маршрут с явным указанием платформ. Для нескольких каналов используйте
`channels: [...]` вместо `channel`. Маршрут с `enabled: false` отключён.

```yaml
routes:
  - name: telegram-to-max
    from: https://t.me/my_channel
    to: "-70123456789"
  - name: max-to-telegram
    from: { platform: max, channel: "-70123456789" }
    to: { platform: telegram, channel: "@my_channel" }
```

1. Добавьте в `.env` `MAX_WEBHOOK_URL=https://example.com/perepost/max` и
   `MAX_WEBHOOK_SECRET`. Сгенерируйте секрет командой `openssl rand -hex 32`.
2. Направьте этот HTTPS-путь через обратный прокси на perepost. При запуске напрямую он
   слушает `127.0.0.1:8090`. В Docker укажите `WEBHOOK_LISTEN=0.0.0.0:8090`
   и добавьте к сервису `ports: ["127.0.0.1:8090:8090"]`, если прокси работает на хосте.
   Пример для nginx внутри существующего HTTPS-сервера:

   ```nginx
   location = /perepost/max {
       client_max_body_size 2m;
       proxy_pass http://127.0.0.1:8090;
   }
   ```

3. Запустите perepost. Он создаст подписку `message_created`, если список подписок пуст, или
   добавит необходимые типы событий к существующей подписке с тем же URL. Для неё укажите
   тот же секрет, с которым её создали. Если бот уже подписан на другой адрес, perepost
   оставит его подписки как есть и сообщит об этом при запуске.

При встречных маршрутах perepost запоминает идентификаторы всех отправленных сообщений,
в том числе частей альбома и длинного текста. Когда эти сообщения приходят с вебхуком
или через Telegram long polling, бот пропускает их.

## Вебхук Telegram

Задайте `TELEGRAM_WEBHOOK_URL=https://example.com/perepost/telegram` и отдельный
`TELEGRAM_WEBHOOK_SECRET`, сгенерированный через `openssl rand -hex 32`. Проксируйте этот
HTTPS-путь на тот же слушатель `WEBHOOK_LISTEN`, что и вебхук MAX. Для совместимости
старое имя `MAX_WEBHOOK_LISTEN` тоже поддерживается.

Остановите прежний экземпляр perepost перед запуском нового. Он зарегистрирует вебхук
через настроенный Bot API с сохранением ожидающих апдейтов. Для возврата к long polling
остановите perepost, вызовите `deleteWebhook` с `drop_pending_updates=false` у того же
Bot API, уберите `TELEGRAM_WEBHOOK_URL` и запустите perepost.

## Синхронизация правок и удалений

```yaml
routes:
  - from: "@my_channel"
    to: "-70123456789"
    sync_edits: true
  - from: { platform: max, channel: "-70123456789" }
    to: { platform: telegram, channel: "@my_channel" }
    sync_edits: true
    sync_deletes: true
```

Оба флага по умолчанию выключены. Если одна направленная пара каналов встречается в
нескольких маршрутах, достаточно включить флаг в одном из них.

- `sync_edits` обновляет текст и подписи оригинала. Вложения остаются прежними.
  При изменении длины переиспользуются существующие части, добавляются недостающие
  и удаляются лишние текстовые части, где это разрешает платформа.
- `sync_deletes` удаляет все известные копии при удалении оригинала из MAX.
  Telegram Bot API позволяет удалять сообщения младше 48 часов. Для источника Telegram
  `sync_deletes` недоступен, поскольку обычный Bot API не сообщает об удалении поста из канала.

Правка зеркальной копии не меняет оригинал. Синхронизация опирается на связи с копиями,
которые perepost записал при публикации. У ранее пересланных постов без такой записи
копии остаются как есть.

### Неизвестный результат публикации

Найдите в журнале поля `source`, `post` и `destination`. Проверьте, появились ли сообщения
в канале назначения. Остановите perepost и вызовите `perepost -resolve-uncertain SOURCE POST
DESTINATION ID [ID...]` с ID опубликованных сообщений. Для MAX используйте `body.mid`,
для Telegram — числовой `message_id`. Если публикации точно не было, передайте `none`
вместо списка ID. В Docker запускайте команду через
`docker compose run --rm --no-deps perepost -resolve-uncertain …`. Затем запустите perepost.
Ранее записанные ID частей поста сохраняются, новые добавляются к ним.

## Видео больше 20 МБ

Облачный Bot API отдаёт ботам файлы только до 20 МБ. Снимает лимит собственный сервер Bot API —
официальный [telegram-bot-api](https://github.com/tdlib/telegram-bot-api) в режиме `--local`. Он
уже описан в `docker-compose.yml` и включается переменными:

1. Получите `api_id` и `api_hash` на [my.telegram.org](https://my.telegram.org) → API development
   tools (понадобится вход по номеру телефона; значения не секретны так, как токен бота, но и
   публиковать их не стоит).
2. Допишите в `.env`:

   ```env
   COMPOSE_PROFILES=bot-api
   TELEGRAM_API_ID=1234567
   TELEGRAM_API_HASH=0123456789abcdef0123456789abcdef
   TELEGRAM_API_URL=http://telegram-bot-api:8081
   ```

3. Один раз отвяжите бота от облачного сервера — иначе Telegram не гарантирует доставку постов
   на свой сервер:

   ```bash
   curl "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/logOut"
   ```

4. `docker compose up -d`.

Сервер кладёт скачанные файлы на общий том, perepost передаёт их в MAX потоком с диска (память не
растёт даже на видео в 2 ГБ) и сразу удаляет. Вернуться на облачный Bot API: уберите эти четыре
строки из `.env`, вызовите `logOut` уже у своего сервера
(`docker compose exec telegram-bot-api wget -qO- http://localhost:8081/bot<TOKEN>/logOut`) и
подождите 10 минут — раньше облако бота не примет.

## Запуск без Docker

Бот — один файл без зависимостей. Возьмите архив для своей архитектуры в
[Releases](https://github.com/smotim/perepost/releases) и запустите через systemd:

```bash
tar xzf perepost_*_linux_amd64.tar.gz
sudo install perepost /usr/local/bin/
sudo mkdir -p /etc/perepost
sudo cp .env.example /etc/perepost/env                 # заполнить
sudo cp config.example.yaml /etc/perepost/config.yaml  # если каналов несколько
sudo cp perepost.service /etc/systemd/system/ && sudo systemctl enable --now perepost
journalctl -u perepost -f
```

При запуске без systemd по умолчанию SQLite создаётся в текущем каталоге. Путь можно задать
через `STATE_FILE`. Для Docker и systemd предусмотрено постоянное хранилище.

## Как узнать, что бот не работает

Две необязательные переменные в `.env`:

- **`HEARTBEAT_URL`** — пульс. Раз в 5 минут бот проверяет, что Telegram и MAX отвечают и он всё ещё
  администратор всех каналов, и при успехе отправляет POST на этот адрес. Если пульс перестал
  приходить, мониторинг поднимает тревогу: так видно и упавший сервер, и снятого с админов бота
  (посты при этом просто перестают приходить, без ошибок). Подойдут heartbeat-мониторы GlitchTip,
  [healthchecks.io](https://healthchecks.io) и аналоги.
- **`TELEGRAM_ADMIN_ID`** — кому писать в Telegram. Бот сообщает о запуске, о посте, который не
  удалось перенести целиком, и о том, что проверка перестала или снова начала проходить. Чтобы бот
  мог написать, откройте его и нажмите «Старт».

## Как это работает

- Посты забираются из Telegram через HTTPS-вебхук или длинным опросом (long polling),
  из MAX — через HTTPS-вебхук.
  Пост сначала записывается в SQLite и только затем подтверждается платформе.
- Альбом Telegram присылает отдельными сообщениями. Бот ждёт две секунды после последней части и
  отправляет альбом целиком.
- Вложение скачивается один раз и загружается каждому получателю. Чтение и загрузка вложений
  повторяются при временных сбоях. При публикации повторяются только явно отклонённые запросы,
  например при ответе 429.
- API MAX (`platform-api2.max.ru`) с июля 2026 подписан сертификатом НУЦ Минцифры «Russian Trusted
  Root CA». Он встроен в бота ([`certs/`](certs), SHA-256 `D2:6D:2D:02:…:CA:8E:CF:31`), и доверяет
  ему бот только в запросах к MAX; Telegram проверяется стандартным набором сертификатов.
- Пока бот не работал, Telegram хранит посты сутки: после перезапуска они будут пересланы.
- При остановке бот досылает полученные посты до 50 секунд. Посты, оставшиеся в очереди,
  обрабатываются после запуска.
